ns_chol: Newton–Schulz forward, Cholesky backward

Causal BW (renorm, shared statistics) on nanoGPT shakespeare_char, the best recipe of bw_nanogpt_study.html: B = 64, T = 256, 6 layers, C = 384, dropout 0, lr 1.5e-3, 5000 steps, one H100.

Summary.
  • BW can whiten with Cholesky (cheap) or with Newton–Schulz (symmetric, ZCA whitening: lower loss, but 21.6 instead of 15.7 ms / step). ns_chol uses each where it is cheap, and gets Newton–Schulz's loss at Cholesky's step time.
  • The gain is in steps, not step time: an ns_chol step costs the same as a Cholesky step (15.77 against 15.72 ms; both slower than LayerNorm's 13.94), but reaches a given loss in fewer steps (4214 against 4438 to LayerNorm's final loss).
  • With the same hyperparameters for both, BW with ns_chol reaches LayerNorm's final train loss in 4214 instead of 5000 steps: −4.7% wall-clock time against LayerNorm, compared with +0.1% for Cholesky (mean of 3 seeds).
  • ns_chol is now the default (bw_whiten="ns_chol", bw_ns_iters=10 in train.py); --bw_whiten=cholesky or --bw_whiten=ns switch back. It needs renorm with batch statistics; without them BW uses Cholesky.

How it works

The layer. Each MLP input is normalized by one BW layer that now also does the needed part of LayerNorm. Before, it was BW followed by a separate LayerNorm with its own gain and bias. Now BW is followed by a LayerNorm without gain or bias, applied inside the same fused BW function (native LayerNorm kernels, forward and backward), with no separate LayerNorm module. The per-token normalization is what is needed after BW; its gain and bias are redundant with BW's own γ and β, and dropping them does not change the loss (bw_nanogpt_study.html, “Do we need the LayerNorm after BW?”). All BW runs below use this layer.

  • Forward: Newton–Schulz. The whitening matrix applied to the activations is the symmetric one, A−1/2 of the running covariance, from 10 Newton–Schulz iterations. With renorm the forward only needs the matrix from the previous step, so Newton–Schulz is never computed inside the forward pass: it computes next step's matrix, in parallel with the backward pass (below), and costs almost no time.
  • Backward: Cholesky. The gradient is the closed-form Cholesky backward, with this batch's Cholesky factor L. This avoids backpropagating through the 10 Newton–Schulz iterations, which is what makes plain Newton–Schulz slow.
  • Why the two fit together: a symmetric whitening matrix and the Cholesky one differ only by a rotation, A−1/2 = Q L−1 with Q orthogonal. With Q held constant, the gradient through the symmetric matrix is exactly the Cholesky gradient. The only approximation is that the gradient ignores how Q changes with the covariance.

What runs when (one BW layer, training step t)

  1. Forward, main stream: Y = γ WR(x − μR) + β, one matrix product. WR was computed during step t−1; no covariance, Cholesky or Newton–Schulz here, so the next layer starts right away.
  2. Side CUDA stream, overlapping the later layers' forward: this batch's statistics (XTX and the mean), the running-covariance update and its Cholesky factor. Only the backward and the next step need them.
  3. Backward: the main stream computes the gradient with the Cholesky formula. At the same time the side stream runs the 10 Newton–Schulz iterations on the updated covariance, producing next step's WR, overlapped with the backward of this layer and the layers below.
  4. Step t+1: the forward uses that WR, long finished by then.

"In parallel" means concurrently on the GPU, on a second CUDA stream, not across layers: the forward is still layer after layer, but each layer's extra work is not needed by anything later in the same forward. The placement matters: running Newton–Schulz on the side stream during the forward made the side stream fall behind, so the backward waited for the last layers' Cholesky factors (16.98 ms / step instead of 15.77).

  • Loss: ns_chol matches Newton–Schulz (4214 against 4232 steps) and beats Cholesky (4438 steps).
  • Step time: ns_chol costs the same as Cholesky (15.77 against 15.72 ms).

Tried, did not help

  • Fewer iterations: 7 Newton–Schulz iterations lose most of the gain, 3 or 5 diverge. 10 are needed.
  • BW in layers 0, 2, 4 only (14.8 ms / step): fewer BW layers lose quality, so about the same wall-clock time as all 6 layers.
  • Newton–Schulz replayed from a CUDA graph: same values, but much slower (26–38 ms / step) next to the side stream.
